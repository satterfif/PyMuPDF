Getting Started

Two command-line tools for scanned PDFs — split a PDF into pages, and make a scanned page searchable. Written for your first time using them.

On this page

  2. Tool 1 — Split a PDF into pages
  3. Tool 2 — Make a scanned page searchable
  4. Using both together
  5. When something goes wrong

These two tools do one job each, and they're often used together:

  • PDF Splitter — takes one PDF and breaks it into single-page PDFs (or pulls out just the pages you want).
  • OCR Merge — takes a scanned (image-only) page plus its OCR text, and produces a copy you can search and copy text from. It looks identical; it's just no longer "just a picture."

You run them by typing a command in a terminal. Don't worry if that's new — every command you need is written out below, ready to copy.

1 What you need first

Both tools need Python (version 3.10 or newer) with the PyMuPDF library available. To check whether you're ready, open a terminal in the project folder and run:

python -c "import pymupdf; print('ready')"

If it prints ready, you're set. If it says No module named 'pymupdf', install it first:

pip install pymupdf

Tip: Run all the commands on this page from the top folder of the project (the one that contains the scripts folder). If a command can't find a file, that's the usual reason — check which folder your terminal is in.

2 Split a PDF into pages

scripts/pdf_splitter_cli.py

Say you have Invoices.pdf and you want each page as its own file.

Step 1. Run the splitter

python scripts/pdf_splitter_cli.py "Invoices.pdf"

Step 2. Find your pages

The tool creates a folder named after your PDF, with a pages folder inside it:

Invoices/pages/page_001.pdf
Invoices/pages/page_002.pdf
Invoices/pages/page_003.pdf
...

That's it. One file per page, numbered in order.

Common variations

You want…Command
Pages saved to a specific folder python scripts/pdf_splitter_cli.py "Invoices.pdf" --output-dir "C:/Output"
Only certain pages, as one file python scripts/pdf_splitter_cli.py "Report.pdf" --pages "1-5, 8, 10-15"

With --pages, you get a single file named Report_pages.pdf holding just those pages (here: 1 through 5, 8, and 10 through 15). Page numbers start at 1.

Good to know: the splitter won't overwrite your original — it only writes new files. If output files with the same names already exist, they're replaced.

3 Make a scanned page searchable

scripts/ocr_merge_cli.py

A scanned page is really just a picture of text — you can't select or search it. If you already have the OCR results for that page (as a JSON file), this tool merges them back onto the page so you can search and copy.

Before you start: this tool does not do the OCR itself. It expects you already have the OCR text as a JSON file (the kind Microsoft Dynamics / Azure produces) next to your PDF. If you don't have that JSON yet, that step happens before this tool.

Step 1. Run the merge

Give it the scanned page and its matching JSON:

python scripts/ocr_merge_cli.py page_005.pdf page_005_formatted.json

Step 2. Open the result

You get a new file, final_page_005.pdf, right next to the original. It looks exactly the same — but now open it in any PDF viewer, press Ctrl+F, and search for a word you can see on the page. It gets found and highlighted.

Wrote searchable PDF: .../final_page_005.pdf

Common variations

You want…Command
Output in a specific folder python scripts/ocr_merge_cli.py page_005.pdf page_005_formatted.json --output-dir "C:/searchable"
To pick the font used python scripts/ocr_merge_cli.py page_005.pdf page_005_formatted.json --font "C:/Windows/Fonts/segoeui.ttf"

Why the font matters: the tool embeds a font so accented and non-English text (like "Österreich") stays searchable. It uses a system font automatically. Only pass --font if it tells you it couldn't find one.

4 Using both together

The common real-world flow: you have one big scanned PDF and want every page searchable. Split first, then merge each page.

1. Split the scan into pages:

python scripts/pdf_splitter_cli.py scanned.pdf

2. Merge each page with its OCR JSON. On Windows PowerShell or a Bash shell you can loop; here's Bash:

# for every page, merge its matching _formatted.json if it exists
for pdf in scanned/pages/page_*.pdf; do
  json="${pdf%.pdf}_formatted.json"
  [ -f "$json" ] && python scripts/ocr_merge_cli.py "$pdf" "$json"
done

Each page becomes a final_page_NNN.pdf you can search. Done.

5 When something goes wrong

Both tools tell you plainly what happened. Here are the messages you're most likely to see the first time, and what to do.

PDF Splitter

MessageWhat it means / fix
Input PDF does not existThe path is wrong. Check spelling; wrap paths with spaces in quotes.
Input file must be a PDFYou pointed it at something that isn't a .pdf.
Password-protected PDF is not supportedRemove the password in a PDF viewer first, then split.
... out of rangeYour --pages asked for a page the document doesn't have. Use numbers within the page count.

OCR Merge

MessageWhat it means / fix
PDF already contains a text layerThat page is already searchable — you don't need to merge it.
Invalid OCR JSON: ...The JSON isn't the expected shape. Confirm it's the OCR export for that exact page.
... is outside the normalized 0-1 rangeThe JSON coordinates aren't normalized as expected — check your OCR export settings.
No Unicode-capable TTF font foundAdd --font pointing at a .ttf file (e.g. a Windows font).
Text is searchable but some words look garbledThat's the OCR quality, not a bug. The tool places whatever text the OCR produced.

For automation: both tools exit with code 0 on success and a non-zero code on failure, so a tool like Power Automate Desktop can tell success from failure automatically. The splitter also supports --json for a machine-readable result.

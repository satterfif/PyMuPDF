PDF Splitter — Improvement Ideas

Generated 2026-07-24 · Focus: PDF Splitter CLI + GUI · Axes: split modes, CLI ergonomics, GUI capabilities, automation integration

Grounding Context

Current state: A 117-line CLI (pdf_splitter_cli.py) that splits PDFs into one-page-per-file using PyMuPDF's insert_pdf(). A Flask testing GUI with drag-and-drop upload and job polling. A 27MB portable .exe for Power Automate Desktop. 4 unit tests.

Top Ideas (Ranked)

1. Split by page ranges

split modesCLI ergonomics

Add --pages "1-5, 8, 10-15" to extract specific pages or ranges into a single output PDF. This is the #1 most-requested feature across all PDF splitting tools.

PyMuPDF's doc.select([page_list]) makes this trivial — pass a list of 0-based page indices, then save. Covers the "extract subset" use case Power Automate's built-in action already supports, making your tool competitive.

2. Auto-create output folder with --mkdir flag

CLI ergonomicsautomation integration

Add a --mkdir / --create-dir flag that creates the output directory if it doesn't exist. Keep the current "must exist" behavior as default for safety, but let automation workflows opt in.

The current "folder must already exist" requirement forces Power Automate flows to add a "Create folder" step before every split. One flag eliminates that. Low complexity, high workflow value.

3. Output filename templates

CLI ergonomicsautomation integration

Add --name-template "{source}_{n:03d}.pdf" with tokens: {source} (input stem), {n} (page number), {total} (page count), {bookmark} (nearest bookmark title). Default stays current behavior.

Enterprise users rank naming control as a top differentiator (PDFsam supports [BOOKMARK_NAME], [FILENUMBER]). Enables downstream workflows to parse page info from filenames without a manifest.

4. JSON structured output mode

automation integrationCLI ergonomics

Add --json flag that outputs a JSON object: {"status": "ok", "input": "...", "pages": 12, "output_dir": "...", "files": [...]}. Power Automate can parse this with "Convert JSON to custom object".

Current stdout is human text. Automation orchestrators need machine-parseable output. Also enables the GUI to call the CLI as a subprocess and parse results instead of reimplementing split logic.

5. Split by bookmarks/TOC

split modes

Add --by-bookmarks [--level N] to split at each bookmark boundary. Default to top-level (level 1). Each output file named after the bookmark title (sanitized).

PyMuPDF's doc.get_toc() returns [(level, title, page), ...]. Split at page boundaries where level ≤ N changes. Covers chapter extraction, contract section splitting, and report disaggregation — all high-value enterprise workflows.

6. Batch mode (multiple input files)

CLI ergonomicsautomation integration

Accept multiple positional arguments or a glob pattern: PDFSplitter-CLI.exe *.pdf. Process each sequentially with per-file status output. Exit code = number of failures (0 = all succeeded).

Current design requires one invocation per file. In Power Automate "For each" loops, this means N process launches. Batch mode reduces overhead for 50+ file jobs from minutes to seconds of process-start latency.

7. Visual page selector in GUI

GUI capabilities

After uploading a PDF, render page thumbnails (PyMuPDF's page.get_pixmap()) and let the user click to select/deselect pages before splitting. Show a grid of thumbnails with checkboxes.

Sejda and SmallPDF both differentiate on visual page selection. For a testing GUI, this makes it trivial to verify specific pages split correctly. PyMuPDF can render thumbnails at 0.2x scale in milliseconds per page.

8. Split every N pages

split modes

Add --every N to produce chunks of N pages each (last chunk may be shorter). Common use: split a 100-page report into 10-page sections for email attachment limits.

qpdf's --split-pages=N and PDFsam's "split every N pages" are heavily used. Implementation: simple loop with insert_pdf(from_page=i*N, to_page=min((i+1)*N-1, total-1)).

9. Progress reporting for large PDFs

CLI ergonomicsGUI capabilities

Add --progress flag that prints page N/total to stderr as each page completes. GUI already has polling infrastructure — wire per-page updates into the job status.

A 500-page PDF takes seconds of silence currently. Progress prevents users from killing the process early. stderr keeps stdout clean for piping/parsing.

10. Granular exit codes

automation integration

Differentiate exit codes: 0 = success, 1 = partial failure (some pages failed), 2 = input error (file not found, not PDF), 3 = permission error, 4 = password protected. Document the codes.

Current binary 0/1 forces Power Automate flows to parse stderr for error type. Granular codes enable "If exit code = 4 then try with password" branching without text parsing.

Additional Candidates

11. Split by blank pages (scan delimiter)

split modes

Detect blank pages as section delimiters in batch-scanned documents. --by-blanks splits before each blank page and optionally removes the blank.

Common in document scanning workflows where a blank sheet separates documents in a stack feed. PyMuPDF can detect blanks via page.get_text() == "" + pixmap whiteness check.

12. Merge mode (complement to split)

split modesCLI ergonomics

Add --merge file1.pdf file2.pdf -o combined.pdf as a complementary operation. Natural pair to split — reassemble after review/editing.

PyMuPDF's insert_pdf() already does this. Users who split often need to recombine subsets. Keeps the tool self-contained for round-trip workflows.

13. Desktop tray app (pywebview)

GUI capabilities

Package the Flask GUI into a pywebview desktop window (like auto-pdf-rotate). Adds native drag-and-drop, system tray icon, and eliminates browser dependency.

Follows the proven auto-pdf-rotate pattern. Makes the GUI feel like a proper tool rather than a dev testing server.

Rejected Ideas (with reasons)

Show rejected ideas

AI/LLM-guided split points

Use an LLM to decide where to split based on content semantics.

Rejected: Overkill for a local tool. Adds LLM dependency (cost, latency, API key requirement) for a niche feature. iLovePDF offers this as a cloud service — wrong fit for a portable CLI.

Multi-language GUI (i18n)

Add zh-CN and other language support like auto-pdf-rotate.

Rejected: This is a testing GUI, not a shipped product. English-only is fine for the intended single-user developer workflow.

Cloud/S3 streaming support

Read PDFs from and write to cloud object storage.

Rejected: The tool's value proposition is local/portable operation for Power Automate Desktop. Cloud workflows have entirely different toolchains (AWS Lambda + pdfcpu). Scope creep.

PDF encryption/password handling

Accept a password flag to unlock protected PDFs before splitting.

Rejected for now: PyMuPDF supports doc.authenticate(password), but password-protected files are explicitly rejected as an intentional safety choice. Could revisit if workflows demand it, but not a priority.

Watch-folder daemon mode

Monitor a folder and auto-split any PDF dropped into it.

Rejected: Power Automate Desktop already provides the "watch folder → trigger action" loop. Adding a daemon duplicates the orchestrator's job and complicates the portable-exe lifecycle (start/stop/crash recovery).
